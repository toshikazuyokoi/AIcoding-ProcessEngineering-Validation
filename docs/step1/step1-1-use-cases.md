## 2. ユースケース詳細

### UC-001: ユーザー登録
**概要**: 新規ユーザーがシステムにアカウントを作成する
**アクター**: AC-002 (ゲストユーザー)
**目的**: システム利用開始のためのアカウント作成
**頻度**: 低頻度（初回のみ）

#### 事前条件
- ユーザーが未認証状態である
- 必要な入力項目が明確である

#### 主要シナリオ
1. ユーザーが登録ページにアクセスする
2. 名前、メールアドレス、パスワードを入力する
3. システムが入力値をバリデーションする
4. システムがユーザー情報をデータベースに保存する
5. システムが登録完了メッセージを表示する
6. ユーザーがログイン状態になる

#### 代替シナリオ
**A1: 入力値エラー**
- 3a. バリデーションエラーが発生する
- 3b. システムがエラーメッセージを表示する
- 3c. ユーザーが入力を修正する
- 3d. メインシナリオの3に戻る

**A2: 重複メールアドレス**
- 4a. 既存ユーザーと同じメールアドレスが検出される
- 4b. システムが重複エラーメッセージを表示する
- 4c. ユーザーが別のメールアドレスを入力する
- 4d. メインシナリオの3に戻る

#### 事後条件
- 新規ユーザーアカウントが作成される
- ユーザーが認証状態になる
- ダッシュボードにリダイレクトされる

#### 非機能要件
- **セキュリティ**: パスワードハッシュ化必須
- **バリデーション**: メール形式、パスワード強度チェック
- **応答時間**: 登録処理3秒以内

### UC-002: ユーザーログイン
**概要**: 既存ユーザーがシステムにログインする
**アクター**: AC-002 (ゲストユーザー)
**目的**: システムへの認証済みアクセス
**頻度**: 高頻度（毎セッション）

#### 事前条件
- ユーザーアカウントが存在する
- ユーザーが未認証状態である

#### 主要シナリオ
1. ユーザーがログインページにアクセスする
2. メールアドレスとパスワードを入力する
3. システムが認証情報を検証する
4. システムがセッションを作成する
5. ダッシュボードにリダイレクトする

#### 代替シナリオ
**A1: 認証失敗**
- 3a. メールアドレスまたはパスワードが間違っている
- 3b. システムが認証エラーメッセージを表示する
- 3c. ユーザーが正しい情報を入力する
- 3d. メインシナリオの3に戻る

#### 事後条件
- ユーザーが認証状態になる
- セッションが確立される

### UC-004: タスク作成
**概要**: ユーザーが新しいタスクを作成する
**アクター**: AC-001 (一般ユーザー)
**目的**: 管理したいタスクの登録
**頻度**: 高頻度（日常使用）

#### 事前条件
- ユーザーがログイン済みである
- タスク作成画面にアクセスできる

#### 主要シナリオ
1. ユーザーがタスク作成ボタンをクリックする
2. タスク名、説明、優先度、カテゴリを入力する
3. システムが入力値をバリデーションする
4. システムが新規タスクを作成・保存する
5. システムがタスク一覧画面に遷移する
6. 作成されたタスクが一覧に表示される

#### 代替シナリオ
**A1: 必須項目未入力**
- 3a. タスク名が空の場合
- 3b. システムが必須項目エラーを表示する
- 3c. ユーザーが必須項目を入力する
- 3d. メインシナリオの3に戻る

#### 事後条件
- 新規タスクが作成される
- タスク一覧に追加される
- ユーザーに成功メッセージが表示される

**アクター**: AC-001 (一般ユーザー)
**目的**: 不要タスクの除去
**頻度**: 低頻度（必要時のみ）

#### 事前条件
- ユーザーがログイン済みである
- 削除対象のタスクが存在する
- タスクの所有者である

#### 主要シナリオ
1. ユーザーがタスク一覧で削除対象を選択する
2. 削除ボタンをクリックする
3. システムが削除確認ダイアログを表示する
4. ユーザーが削除を確認する
5. システムがタスクを削除する

- 1a. タスクの所有者でない場合
- 1b. システムが権限エラーを表示する

#### 事前条件

- カテゴリ管理画面にアクセスできる

#### 主要シナリオ
1. ユーザーがカテゴリ管理ページにアクセスする
2. 現在のカテゴリ一覧が表示される
3. ユーザーがカテゴリを作成・編集・削除する
4. システムが変更内容をバリデーションする
5. システムがカテゴリ情報を更新する
6. システムが変更完了メッセージを表示する

#### 代替シナリオ
**A1: カテゴリ重複エラー**

**A2: 使用中カテゴリ削除エラー**

- 4b. システムが削除不可メッセージを表示する

- **応答時間**: 更新処理1秒以内

### UC-010: データ永続化
**概要**: システムデータの永続的保存と管理
**アクター**: AC-003 (システム)
**目的**: データの永続性保証
**頻度**: 常時（全操作で実行）

#### 事前条件
- システムが正常に動作している
- データベース接続が確立されている

#### 主要シナリオ
1. システムがデータ変更操作を検知する
2. システムがトランザクションを開始する
3. システムがデータをバリデーションする
4. システムがデータベースに変更を反映する
5. システムがトランザクションをコミットする
6. システムが操作ログを記録する

#### 代替シナリオ
**A1: データベース接続エラー**
- 2a. データベース接続が失敗した場合
- 2b. システムが接続リトライを実行する
- 2c. リトライ失敗時はエラーログを記録する
- 2d. ユーザーにシステムエラーを通知する

**A2: データ整合性エラー**
- 4a. データベース制約違反が発生した場合
- 4b. システムがトランザクションをロールバックする
- 4c. システムがエラーログを記録する
- 4d. ユーザーにデータエラーを通知する

#### 事後条件
- データが永続的に保存される
- 操作ログが記録される
- データ整合性が保証される

#### 非機能要件
- **信頼性**: ACID特性の保証
- **パフォーマンス**: データベース操作最適化
- **バックアップ**: 定期的なデータバックアップ
