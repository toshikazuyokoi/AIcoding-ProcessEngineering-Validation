## 1. 実行可能性最優先設計思想 概要

### 1.1 設計思想の定義
実行可能性最優先設計思想は、**「理論の価値は実践での実行可能性によってのみ測定される」**という根本原則に基づき、抽象的記述を完全に排除し、実践者が確実に実行できる具体的手順の提供を最優先とする革新的設計アプローチである。

```yaml
executability_first_philosophy:
  core_principle: "実行可能性至上主義"
  fundamental_belief: "理論の価値 = 実践での実行可能性"
  design_mandate: "抽象論完全排除・具体的実行手順必須化"
  success_criteria: "実践者が迷わず確実に実行できること"
  
  philosophical_foundation:
    pragmatic_supremacy: "実用主義の絶対的優位性"
    concrete_over_abstract: "具体性の抽象性に対する絶対的優先"
    practitioner_centricity: "実践者中心主義"
    execution_guarantee: "実行保証責任"
```

## 2. 実行可能性最優先の設計原則

### 2.1 抽象論完全排除原則

```yaml
abstraction_elimination_principle:
  elimination_mandate:
    abstract_descriptions: "「品質を確認する」→「品質ゲート実行チェックリストを用いた証拠収集」"
    vague_instructions: "「適切に実施する」→「STEP1-7の具体的実行手順に従って実施する」"
    ambiguous_responsibilities: "「担当者が実施」→「品質ゲートキーパーが単独権限で判定」"
    conceptual_explanations: "「理論的には」→「実践的には以下の手順で」"
    
  concrete_transformation_rules:
    what_to_do: "何をするか → 具体的作業項目の明示"
    how_to_do: "どうするか → ステップバイステップ手順"
    who_does_it: "誰がするか → 明確な責任者指名"
    when_to_do: "いつするか → 具体的タイミング・条件"
    where_to_record: "どこに記録するか → 具体的文書・システム"
    how_to_verify: "どう確認するか → 検証方法・基準"
    
  forbidden_expressions:
    - "適切に" → "以下の基準に従って"
    - "必要に応じて" → "以下の条件が満たされた場合"
    - "十分に" → "以下の完了基準を満たすまで"
    - "効果的に" → "以下の手順に従って"
    - "品質を確保して" → "品質ゲートを通過して"
```

