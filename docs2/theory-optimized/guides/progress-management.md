# 進捗管理ガイド (500 tokens)

## 進捗可視化の方法

### 階層的進捗管理
```
プロジェクト全体進捗 (100%)
├── Category 1 進捗 (25%)
│   ├── Task 1.1 (完了)
│   ├── Task 1.2 (進行中 80%)
│   └── Task 1.3 (未着手)
├── Category 2 進捗 (60%)
└── Category 3 進捗 (10%)
```

### 進捗指標の定義
**完了率**: 完了タスク数 / 総タスク数 × 100
**品質率**: 品質ゲート通過数 / 実施ゲート数 × 100
**効率率**: 実績工数 / 計画工数 × 100

### 可視化ツール
- **ガントチャート**: スケジュール進捗
- **バーンダウンチャート**: 残作業量推移
- **カンバンボード**: タスク状態管理

## 品質指標の監視

### 品質ゲート通過率
```
ゲート1 (要件): 通過率 95%
ゲート2 (設計): 通過率 88%
ゲート3 (実装): 通過率 92%
ゲート4 (テスト): 通過率 85%
```

### 品質メトリクス
**コード品質**:
- 静的解析スコア
- テストカバレッジ
- 複雑度指標

**設計品質**:
- アーキテクチャ適合性
- インターフェース整合性
- 非機能要件達成度

### 品質トレンド分析
- 週次品質レポート
- 品質改善トレンド
- 問題発生パターン分析

## アクションアイテム管理

### 課題分類
**緊急度 × 重要度マトリックス**:
```
        | 重要 | 普通 |
--------|------|------|
緊急    |  A   |  B   |
普通    |  C   |  D   |
```

### 対応優先順位
1. **A (緊急×重要)**: 即座対応
2. **B (緊急×普通)**: 当日対応
3. **C (普通×重要)**: 計画的対応
4. **D (普通×普通)**: 余裕時対応

### エスカレーション基準
**自動エスカレーション**:
- 進捗遅延 > 20%
- 品質ゲート失敗 > 2回
- 重大バグ発生

**手動エスカレーション**:
- 技術的課題
- リソース不足
- 要件変更

## リスク管理

### リスク監視指標
- **スケジュールリスク**: 遅延日数
- **品質リスク**: 欠陥密度
- **技術リスク**: 未解決課題数

### 早期警告システム
**黄色警告** (注意レベル):
- 進捗遅延 10-20%
- 品質指標低下
- チーム負荷増加

**赤色警告** (危険レベル):
- 進捗遅延 > 20%
- 品質ゲート連続失敗
- 重大技術課題

### 対策アクション
1. **予防策**: リスク発生前の対策
2. **軽減策**: リスク影響の最小化
3. **回避策**: リスク要因の除去
4. **受容策**: リスク受け入れと監視
