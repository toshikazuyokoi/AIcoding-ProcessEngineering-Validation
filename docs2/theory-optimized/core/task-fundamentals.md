# タスク基本原則 (300 tokens)

## カテゴリ単位管理の基本

### 規模判定の基本原則
**推定ファイル数による分類**:
- **小規模 (< 10ファイル)**: レイヤー単位管理
- **中規模 (10-30ファイル)**: 機能モジュール単位管理  
- **大規模 (> 30ファイル)**: 実装フェーズ単位管理

**調整係数の適用**:
```
調整後ファイル数 = 推定ファイル数 × 技術複雑度 × ドメイン複雑度 × チーム係数
```

### 選択的展開の概念
**展開レベル判定**:
- **レベル1 (基本)**: ファイル名・主要クラス・メソッドのみ
- **レベル2 (標準)**: インターフェース・主要ロジック含む
- **レベル3 (詳細)**: 完全な実装詳細まで展開

**判定基準**:
- ファイルの重要度 (Core/Important/Supporting)
- 複雑度 (High/Medium/Low)
- 依存関係の影響度

### 進捗管理の基本

#### 可視化手法
- **進捗率**: 完了タスク数 / 総タスク数
- **品質指標**: 品質ゲート通過率
- **リスク指標**: 遅延・品質問題の早期警告

#### 管理単位
- **カテゴリレベル**: 機能単位の進捗管理
- **タスクレベル**: 個別タスクの詳細管理
- **品質レベル**: 品質ゲート通過状況

## 実装戦略

### 並列開発の原則
1. **依存関係の最小化**: モジュール間の結合度を下げる
2. **インターフェース先行**: 契約を先に定義
3. **段階的統合**: 小さな単位で継続的に統合

### 品質確保の原則
1. **早期テスト**: 実装と並行してテスト実行
2. **継続的検証**: 自動化されたチェック
3. **段階的レビュー**: 適切なタイミングでのレビュー

### リスク管理の原則
1. **早期発見**: 問題の兆候を早期に検出
2. **迅速対応**: 発見した問題への迅速な対応
3. **予防措置**: 同様問題の再発防止
